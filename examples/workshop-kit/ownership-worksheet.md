# Ownership worksheet

Fill this in before the model is used for anything. Write a **role or job title**, not a person's name, so the
answer survives when people move on. The reasoning is in
[Who owns what](../../docs/2-what-a-model-looks-like.md#who-owns-what).

## Who is accountable for each part

| Part | Accountable role | Who they must consult |
|---|---|---|
| Types and standards | | |
| Asset identity and hierarchy | | |
| Relationships, and what each measurement means | | |
| Addresses, topics and the running namespace | | |
| Servers, hosting, backup and monitoring | | |
| Review of every connection (security) | | |
| Priorities and disputes | | |
| **The namespace as a whole** (one role only) | | |

## Questions to settle

| Question | Our answer |
|---|---|
| Who is called when a value on a screen is wrong at night? | |
| Whose hierarchy does the namespace follow: maintenance or process? | |
| Where is the model kept, and who can change it? | |
| Who approves a change, and how is the approval recorded? | |
| How often is the whole model reviewed? | |
| How long are history, records and old versions of the model kept, and who decides? | |
| What may be given to an AI tool, and what may not? | |
| What happens when the data system itself is unavailable? | |

## A check before you finish

- Every row in the first table has exactly one accountable role.
- No role is accountable for both building a connection and approving it.
- The group that runs the platform is not the one that decides what the data means.
